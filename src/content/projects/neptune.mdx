## Overview

Neptune is a song recognition and recommendation project inspired by Shazam. It explores how a small piece of audio can be used to identify a track and help someone discover more music.

The project combines audio fingerprinting, FFT-based signal processing, and hashing with a web interface built using TypeScript and Next.js. Python, FastAPI, and PostgreSQL make up the rest of its stack.

## From audio to a fingerprint

Raw audio contains far more data than a recognition lookup needs. Audio fingerprinting turns useful features of a recording into a compact representation that can be compared with known tracks.

FFT-based processing helps move from the audio signal to information about its frequencies. That gives a different view of the recording than its waveform alone.

```text
Audio sample → Frequency features → Fingerprint
                                        ↓
                               Compare known tracks
                                        ↓
                                 Recognized song
```

This is a conceptual view of the recognition pipeline. The source repository contains the specific implementation.

## Matching and recommendations

Efficient hashing helps turn recognition into a lookup problem instead of comparing a sample directly with every recording. The goal is to retain useful identifying information while keeping the representation practical to search.

Recognition and recommendation answer different questions. Recognition asks which track a sample belongs to. Recommendations help the listener find another track after that first result.

## Technology choices

- **TypeScript and Next.js** provide the web application.
- **Python** supports the audio-processing side of the project.
- **FastAPI** provides the Python API layer.
- **PostgreSQL** provides relational storage.

## Engineering focus

Neptune brings signal processing and application development into the same project. It is an opportunity to think about how a representation chosen during processing affects the search that comes later.

The fingerprint connects those two worlds: it needs to describe something distinctive about a recording while staying small enough to compare efficiently.
